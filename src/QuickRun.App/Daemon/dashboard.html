When it is good

  1. Your own repository: save the text as quickrun.yml in the repository root, commit it, push it. That is all - anyone who runs the repository from then on gets your config, and the quickrun validate command checks it in a pre-commit hook.
  2. Someone else's repository: use Save as my config. It is kept in QuickRun's own directory, applies to every branch of that repository, and beats a quickrun.yml the repository ships. Nothing is written into the checkout, so --fresh cannot delete it and you cannot commit it by accident.
  3. The schema line at the top of the file gives you the same completion in your own editor - VS Code, JetBrains and anything else that speaks YAML language server.

Full reference: fgilde.github.io/QuickRun/config

From a terminal

Everything the window does, the command line does too - and a few things it does not. 

quickrun                       the tray icon and this window
quickrun --browser             open this page in your browser instead
quickrun --no-tray             no tray icon; the browser is the UI

quickrun run acme/app          clone, check the tools, run it
quickrun run acme/app --ref feature/login
quickrun run acme/app --pr 42
quickrun run acme/app --input apiKey=sk-1 --input port=3000

quickrun validate              check a quickrun.yml
quickrun detect                what it would run without a config
quickrun detect . --save       write that as a quickrun.yml

quickrun ls                    the workspaces on disk
quickrun clean --older-than 30d

quickrun install               autostart and the quickrun:// handler
quickrun update                update in place
quickrun --help                every command and flag

The full reference is in the CLI documentation.

Browser extension

quickrun:// handler checking…

The extension uses quickrun:// to start QuickRun when it is installed but not running. Registering needs no administrator rights: on Windows it is a key under HKCU, on Linux a .desktop file in your home directory, on macOS the QuickRun.app bundle.

Your browsers

Found on this machine. QuickRun cannot put an extension into a browser by itself - Chrome removed that in 2018, and the only mechanism left is a policy that force-installs something you could not then remove. So this goes as far as it honestly can: it opens the right page in the right browser, and leaves the last click to you.

How it works

  1. Install the extension from the download page. Until the store listings are live it is loaded unpacked; that page has the steps.
  2. Nothing to pair: the extension is trusted by its origin, which a web page cannot forge.
  3. Open any repository on GitHub. A Run this button appears next to the branch dropdown, in pull request headers, and on every row of the branch list.
  4. Clicking it does not start anything yet: QuickRun checks the repository out, then the extension shows you the exact commands and waits for your confirmation.

Full documentation: fgilde.github.io/QuickRun
